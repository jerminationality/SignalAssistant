3. UPDATESTATEMACHINE() - STATE TRANSITIONS
===============================================================================

File: src/YIN/FastYINDetector.cpp, Lines 185-308

Called with: (rms, pitchResult, params)

-------------------------------------------------------------------------------
IDLE State (Lines 197-210)
-------------------------------------------------------------------------------
CHECK: Is there a new note onset?
  Conditions:
    - rms > noiseGate * 3.0          (signal above noise floor × 3)
    - rms > lastRMS * 2.0            (2x energy increase)
    - (rms - lastRMS) > 0.08         (absolute jump of 0.08)

  IF YES:
    → m_state = NoteState::ATTACK
    → m_peakRMS = rms
    → m_lastOnsetThreshold = rms
    → Store lastRMS for next frame

  IF NO:
    → Stay in IDLE
    → Update lastRMS

-------------------------------------------------------------------------------
ATTACK State (Lines 213-227)
-------------------------------------------------------------------------------
CHECK: Is pitch confident enough to confirm note?
  Condition:
    - pitchResult.confidence >= yinThreshold (typically 0.10)

  IF YES:
    → m_state = NoteState::SUSTAIN
    → Note confirmed, stable pitch detected

  IF NO:
    → Stay in ATTACK
    → Waiting for confident pitch detection
    → Update peakRMS if rms increased

-------------------------------------------------------------------------------
SUSTAIN State (Lines 230-270)
-------------------------------------------------------------------------------
CHECK 1: Should we release the note?
  Condition:
    - rms < m_peakRMS * releaseRatio (typically 0.35)

  IF YES:
    → m_state = NoteState::RELEASE
    → Note is decaying

CHECK 2: Is there a re-attack (new note plucked)?
  Conditions:
    - rms > lastRMS * 2.0            (2x increase)
    - (rms - lastRMS) > 0.08         (absolute jump)
    - rms > noiseGate * 3.0          (above noise × 3)

  IF YES:
    → m_state = NoteState::ATTACK
    → m_lastOnsetThreshold = lastRMS * 2.0
    → m_peakRMS = rms
    → New note detected during sustain

ALWAYS:
  → m_peakRMS = std::max(m_peakRMS, rms)  // Track peak
  → m_lastRMS = rms

-------------------------------------------------------------------------------
RELEASE State (Lines 273-308)
-------------------------------------------------------------------------------
CHECK 1: Has signal dropped to silence?
  Condition:
    - rms < noiseGate

  IF YES:
    → m_state = NoteState::IDLE
    → Back to waiting for new note

CHECK 2: Is there a re-attack from decay?
  Conditions:
    - rms > lastRMS * 1.8            (1.8x increase, more sensitive)
    - (rms - lastRMS) > 0.05         (absolute jump)
    - rms > noiseGate * 2.0          (above noise × 2)

  IF YES:
    → m_state = NoteState::ATTACK
    → m_lastOnsetThreshold = lastRMS * 1.8
    → m_peakRMS = rms
    → New note plucked during decay

ALWAYS:
  → m_lastRMS = rms

===============================================================================
KEY PROTECTION MECHANISMS
===============================================================================

1. Onset Counter (AtomicNoteState.h)
   → Monotonic uint32_t incremented on ATTACK entry
   → TabEngine compares to detect onsets
   → Never miss onset even if ATTACK lasts 1 frame

2. Pending Onset (TabEngine.cpp:76-108)
   → Stores onset when counter changes but fret = -1
   → Emits note when fret becomes valid
   → Clears after 200ms timeout or signal drop
   → Handles race: onset detected before pitch valid

3. Fret Lock During SUSTAIN (FastYINDetector.cpp:331-334)
   → Once committed to fret during ATTACK, locks for SUSTAIN
   → Prevents F0↔F4 bouncing during decay
   → Decay harmonics/noise cannot change reported fret

4. REPITCH Energy Threshold (TabEngine.cpp:156)
   → Only allow fret changes if energy > 50% of onset threshold
   → Prevents low-energy decay jitter from creating events
   → Real slides/bends still detected (high energy)

5. Fret Stability (FastYINDetector.cpp:344-364)
   → Requires 2 consecutive frames to change fret
   → Exception: First note promoted immediately
   → Exception: SUSTAIN state locks fret completely

===============================================================================
COMMON ISSUES AND FIXES
===============================================================================

Issue: REPITCH spam during decay (F0↔F4 bouncing)
Root Cause: Fret not locked during SUSTAIN, pitch detection unstable
Fix Applied: Lines 331-334 lock fret during SUSTAIN state

Issue: Note ON delay (1-2 seconds)
Root Cause: Using stableFret during ATTACK (waits for stability)
Fix Applied: Line 233 uses detectedFret during ATTACK (immediate)

Issue: Multiple ON/OFF cycles from single pluck
Root Cause: YIN state bouncing, pending onset cleared too aggressively
Fix Applied: Stricter pending onset clearing (lines 96-108)

Issue: False re-triggers during sustain
Root Cause: Re-attack thresholds too sensitive (1.4x)
Fix Applied: Increased to 2.0x for SUSTAIN, 1.8x for RELEASE
